The current workflow already permits repeated `/workflow-implement` calls, but each call sends the same original-plan kickoff. It does not pass the latest review or decisions made while discussing it. `/workflow-revise` passes the saved report but requires a new written request. Review sessions cannot currently save either followup changes or user decisions.

The FRED review session `01a08cfb-06a2-7089-aa89-86a925979e67` illustrates the gap. The user agreed to four changes, discussed another suggestion, and explicitly kept a helper unchanged. The reviewer then summarized those choices so the user could copy them into revision session `01a08d3d-e3cd-7089-aa89-86ab8b9b6ba4`. Some agreed changes also replaced design choices in the approved plan; they were not simply fixes for failed review checks.

Keep the approved plan and completed reviews immutable. Store followups beside them as durable workflow records that reuse planned-change IDs, explanations, and dependency rules. Present accepted followups as additional planned changes, with their source and status visible. An implementation record is evidence of work performed, not an independent review verdict.

Two product choices remain open for user confirmation. This draft recommends saving reviewer suggestions as proposed until the user agrees, while direct user requests become accepted pending work. It also recommends one implementation phase: `/workflow-implement` handles followups without an editor, and `/workflow-revise` remains a manual-request shortcut into the same implementation phase. The separate revision phase would no longer be used for new sessions. These are draft recommendations, not decisions already made by the user.

This change does not implement the FRED revisions, import old conversations automatically, change workflow-artifact retention, automate deployments, or turn every generated review concern into a task. Existing local Git, pull-request delivery, isolated review agents, and plan approval rules remain in place.
