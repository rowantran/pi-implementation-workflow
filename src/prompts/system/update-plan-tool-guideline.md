Use workflow_update_plan with action="prepare" before editing a plan. Edit only the returned draft directory's permitted JSON and Markdown files with native edit or write calls. The tool preserves existing unsaved edits. Planning edits original requirements with implemented:false. Review edits followup definitions and their reading order, never original files; new or revised followups must be false. Implementation edits only implemented booleans in existing change_metadata.json files. Respect the phase-specific allowed edits returned by prepare; finalization enforces field-level restrictions.
Use workflow_update_plan with action="finalize", expectedBaseVersion from prepare, and a concise English description of the entire plan (at most 18 words and 160 characters) to publish a new immutable version. Never describe only the latest edit or diff.
Finalization validates required files, strict JSON metadata, stable slug IDs, readingOrder, and dependency edges. Fix reported errors in the draft and retry; invalid drafts never replace the saved plan. Reconcile stale drafts with the latest version instead of overwriting another session's work. Finalization is a plan snapshot, not a Git commit or implementation verification. All finalized followups become agreed scope when the user runs the next implementation or review phase; there are no decision states, user-message approval citations, separate task stores, or evidence records.
